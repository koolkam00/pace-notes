# Pace Notes: agent entry point

Pace Notes ([splithappens.run](https://splithappens.run)) publishes pacing research from recorded marathon and half-marathon splits. This file holds the standing rules; each names the check that enforces it and the document with the detail. The owner's decisions are quoted and dated in [docs/OWNER_DECISIONS.md](docs/OWNER_DECISIONS.md); procedures are in [docs/OPERATIONS.md](docs/OPERATIONS.md).

## Start here

1. Rules load from the commit you have checked out. Run `git fetch origin` and compare `HEAD` with `origin/main` before relying on them, then start from `origin/main` in a clean worktree on a new branch.
2. Read the [project handoff](docs/PROJECT_HANDOFF.md): its Current state, Open for the owner and Subsystem index, then the contract document of the subsystem you change. Dated records are in [docs/history](docs/history/README.md); read them for evidence, not for the current state.
3. The checks for each kind of change are in [operations: checks by change type](docs/OPERATIONS.md#checks-by-change-type); calculation, import and per-release contracts are in [analysis/README.md](analysis/README.md).
4. Scheduled autopilot runs, and any request to "run the autopilot", follow `autopilot/CONSTITUTION.md` (highest authority) and the playbook in `.claude/skills/pace-notes-autopilot/SKILL.md`. How merges, live checks and automatic reverts work is in `docs/AUTOPILOT.md`. Autopilot runs never edit the files the constitution protects (§6), this file and the handoff among them (`scripts/autopilot-guard.cjs` fails such a pull request); their record is `autopilot/ledger.jsonl`, `autopilot/LEARNINGS.md` and the log issue, so rule 19 does not apply to them.

## Standing rules

### Data access

1. **Access.** Make the source code, complete runner records (including recorded names), exports, database snapshots, overlays and analysis outputs publicly downloadable without an account. Use ordinary unencrypted files; compression is optional. This current access policy supersedes earlier privacy-only instructions. (Files and checksums: [analysis/ACCESS.md](analysis/ACCESS.md); the dated anonymous checks: the handoff's Current state.)
2. **Release assets.** Prefer public GitHub Release assets for large Parquet/SQLite files and backups, with durable anonymous download links, schemas and SHA-256 checksums. Runner data may be opened or stored in the checkout; there is no mandatory privacy boundary around it. Keep statistical cohort thresholds for estimate reliability, not as a restriction on access to full records.
3. **Credentials.** Keep passwords, access tokens and other operational credentials out of datasets and repository files. They are not research data. Public dataset downloads must not depend on credentials or expiring signed URLs.
4. **Half marathons.** Half figures use the separate pin `analysis/half-release.json` and the reviewed policy file it names; linked figures also bind the adopted marathon release, its runner manifest and the weather evidence. The half results, the links between half and marathon records and the scripts that built them are the owner's public CC BY 4.0 releases under rule 1 (owner decision, October 30, 2026: "publish everything and full merge"), fetched anonymously by `analysis/download_half.py`.
   Pages still publish aggregates: every shown group holds at least 100 finishes or pairs and a claim across editions rests on at least 3 editions. A verified edition is stamped in both the snapshot and the corrected edition metadata the pin names; a new snapshot or metadata file shows no half figure until the policy is reviewed again. Half-only figures use verified editions; any figure that uses unverified editions carries the "Includes unverified half results" chip; linked figures use set B (medium or high links, `ns_keys ≤ 3`) and say "records linked by name". Sustained slowdown stays a marathon metric. After any half rebuild run the local source recount (`npm run verify:half-source`); CI fails on a stale receipt, and the half workflow's `source` job rebuilds from the public assets whenever the pin, policy, builders or recount change. (`verify-half`; [docs/HALF_MARATHON.md](docs/HALF_MARATHON.md).)

### Analysis integrity

5. **Pins.** Every visible analysis must use the adopted release in analysis/release.json (including supporting study and runner lookup); weather must match through its separate pin. Do not fall back to historical chart files. Preserve historical numerical evidence in Git history and immutable releases. live.json is current compatibility metadata, with no archived figure payloads. Importers have separate ownership and validation contracts. (Each family's verifier in `npm run verify:data` checks its pin.)
6. **Runner context.** Runner context must additionally match the exact runner-manifest hash, timestamp and edition mapping. Refresh/import the lookup before rebuilding context, then use its dedicated importer and full verifier. Same-edition peer groups require 101 finishes (100 others plus the focused record); finish percentiles exclude the focused record, while pace quartiles include it. Weather and supplied-route elevation remain context, never personal-exposure measurements or finish-time adjustments. (`verify-runner-context`; [detail and source conflicts](docs/RUNNER_CONTEXT_AND_PEERS.md).)
7. **Terrain splits, the one elevation exception** (owner decision, October 23, 2026: "It should use an elevation model"). The planner's and pace band's terrain splits divide the visitor's own goal over a corrected, audited route profile (`analysis/course_terrain/corrections.json`) with one published grade curve. They never change the goal or any finish time, are never fitted to Pace Notes data, never use an uncorrected supplied profile, carry the Published research badge, and ship only on courses marked `band: "terrain"`. (`verify-insights`, `verify-tools`; [tools](docs/TOOLS.md#terrain-splits-owner-decision-october-23-2026).)
8. **All-finisher views.** All-finisher course/weather/downhill views bind both exact runner and context manifests; rebuild after either changes. Their cross-edition rates average editions equally, while onset and finish-time context pool finishes. Keep those denominators distinct and retain history for personal improvement and other longitudinal questions. (`verify-all-finisher-context`; [docs/ALL_FINISHER_ANALYSES.md](docs/ALL_FINISHER_ANALYSES.md).)
9. **Record IDs within a release.** The audited `private-export-20260911-1107`, `private-export-20260912-0934`, `htw-db-2026-10-16-1652` and `private-export-20261021-1050` use canonical raw/feature record IDs with runtime uniqueness, label and full-timing checks. The reviewed `private-export-20261021-0829` is not adopted: its FULL lacks the cross-race identity. September 7 CORE/FULL IDs remain incompatible and require the legacy one-to-one natural match.
10. **Record IDs across releases.** IDs are not stable across releases: 1652 replaced 116,287 0934 IDs (Chicago 2018, Chicago 2019 and Frankfurt 2019 were reloaded), so never carry an ID from one release to another without the runner-manifest mapping (1050 kept every 1652 ID it still holds and changed none of their records). Never infer record alignment from row order or treat cross-race IDs as independently verified people.
11. **Edition policy.** Apply the reviewed release-specific edition policy in `analysis/source_quality.py` after timing checks. Keep its exclusion counts and hashes with every result. Invalid, incomplete, held and selected-field editions cannot supply outcomes or earlier benchmarks. Missing age or recorded gender alone does not remove usable timings from the All cohort.
12. **No inference.** Do not infer missing splits, exact ages, actual halfway timings, historical course validity, runner goals or causal effects.
13. **Guards and floors.** Builder floors (such as 100 finishes per group, 3 editions, the half's 10 pairs per edge slice and 20 editions for its women's band medians) decide what is published; page guards decide what is said. When a tail or bin falls under a floor, narrow the published range; never lower a floor or add a compensating check to keep a chart (October 30, 2026: a lowered half floor was found in review and restored). When a number moves and a guard fails, the fallback shows and the guard is re-judged on its merits, never loosened to keep a headline; a share card whose takeaway fails is withdrawn. A fallback states no reading in any slot (heading, dek, hero figure and its key, caption, table reading row, card, chapter rows, next and night cards). A whole figure under a builder floor is left out with its beat. (The family verifiers, `verify-nuggets`; [half lessons](docs/HALF_MARATHON.md).)

### Site copy and visitor privacy

14. **Pace Notes terms.** Use Pace Notes branding and sustained slowdown terminology in public prose. Preserve the metric: slowdown at least 25% for at least 5 km after 20 km relative to the 5–20 km baseline. Its definition and neutral published-method citation are stated once, on /methodology#sustained-slowdown; other pages link the term there instead of repeating them. Historical field names and compatibility URLs may remain unchanged.
15. **Insights only** (owner decision, October 16, 2026). Methods, definitions, data sources, coverage and limits live only on /methodology (Methods & sources): no calculation, source, coverage, cohort or method-caveat text on any other page. Evidence badges stay as short labels that link to /methodology#evidence. Functional copy (labels, how to use a tool, empty and error states) and short wording disclaimers such as "Not a prediction" stay. Every /methodology#<id> link must name an id the page has. (`verify-ten-analyses`, `verify-research`, `verify-seo` `methods-anchors`.)
   Orientation (owner request, October 22, 2026): the home hero says in one line what Pace Notes is; /about says what it is, where to start (a row per visitor goal), why it exists and how it is made, and links to the /methodology ids for where the data comes from, how releases are checked, the limits and the downloads instead of repeating them; /methodology opens on a four-fact short version.
16. **Runner tools** (`/tools`) label Pace Notes data, published research and official standards with badges and never combine them. Plain calculations from the visitor's own inputs carry no badge. Data shares are observed shares of complete finishes, never "your chance". Qualifying standards are dated and need the annual review in [docs/TOOLS.md](docs/TOOLS.md). The as-run course shape (medians of finishes that made a goal, scaled to it) is retired: observed medians near a goal appear only unscaled, in a Pace Notes data panel, with the sustained-slowdown forewarning, never as a band or on a wristband. (`verify-tools`.)
17. **Words the site never uses.** The owner does not want the word "arithmetic" anywhere on the site. Never "the wall" or "hit the wall" (say "sustained slowdown"), never "your chance" in any form, and never a release tag or its date in visible copy. Enforced by `verify-tools` ("arithmetic" in `app/`, `components/` and `lib/`), `verify-seo` `banned-words` (the three phrases in every built page's text, metadata and JSON-LD), `verify-courses` (the phrases, `private-export`, `htw-db-`, `20260912`, `20261016` and `20261021` on course pages), `scripts/lib/words.cjs` (`BANNED` and `RELEASE_LABEL`, which adds `half-dataset-`, `half-snapshot-` and `runner-links-`, in `verify-charts` and `verify-half`) and `scripts/autopilot-guard.cjs` on autopilot pull requests.
18. **Visitor inputs stay private.** Search text, typed times and other typed values, runner labels, record IDs and birth dates never go into analytics events, URLs sent to analytics or recordings; birth dates never go in URLs. This protects visitors and is separate from rule 1, which publishes the research records. (`lib/analytics-policy.ts` and `lib/replay-policy.ts`, tested by `npm run verify:analytics` and the `privacy-e2e` job, whose S2 types two value sets and fails if a run's own values reach PostHog; `/runners`, `/your-race` and `/report` are never recorded. [Analytics](docs/ANALYTICS.md); constitution §1.1.)

### State, evidence and checks

19. **Record what changed.** Update the handoff's Current state and the owning contract document when a merge changes data contracts, analysis methods, workflow behavior or issue status; move superseded text verbatim to [docs/history](docs/history/README.md), never rewriting it. Date evidence and preserve historical vintage labels.
20. **Four facts, kept apart.** Distinguish release-note claims, measured audit results, repository state and deployed state. Never assume a newer upload has reached the website: write "live" only after reading `https://splithappens.run/version.json` (and `/data/live.json` for data).
21. **Counts carry their release.** Quote a count with the release tag and date it came from. Current counts live in the `REFRESH_<tag>.md` records and the manifests, not in entry or contract documents.
22. **Compatibility names.** Preserve legacy release tags and filenames containing `private` (and the half pin's `private_tag` names) as compatibility identifiers; their names do not determine current access. Check the dated access status in the handoff's Current state before claiming anonymous access works.
23. **Checks.** Run the checks for your change type ([operations](docs/OPERATIONS.md#checks-by-change-type)); calculation changes need the Python tests, site and data changes the CI set. Use the existing analysis and import commands in operations. Documentation-only changes require checking links, mappings and factual consistency, not a new full-data calculation. Never weaken a check to make it pass: find the cause; if a number legitimately moved, change the expectation with a dated comment saying why.

## Practices that have paid off

Short lessons from earlier work; [operations](docs/OPERATIONS.md) holds the procedures.

- **Read the owner's releases before merging data work.** List the releases of both repositories and read every one newer than the pins; a correction release supersedes the metadata it names (October 30, 2026: `half-dataset-20261029-2157` withdrew stamps hours before the half merge). Check, never assume, that IDs join across snapshots. ([Release intake](docs/OPERATIONS.md#release-intake).)
- **Prove anonymous access, and date it.** A ranged GET on the github.com release URL with no credentials (`curl -sSL -r 0-0 -o /dev/null -w '%{http_code}' URL`) answers 206 for a public asset and 404 for a private one. Requests to api.github.com carry the session's credentials and prove nothing; the asset host answers HEAD with 401; doi.org's 302 shows a DOI resolves, while figshare's pages answer scripted clients with a 202 challenge. ([Access checks](docs/OPERATIONS.md#access-checks).)
- **Pin every input by sha256, corrections included,** and fail loudly when a frozen list, a count or a digest differs. Update a reviewed count from a real run after reading the difference, never with `--accept-counts` alone.
- **Write a rule so a stranger can recount it.** A frozen policy states its reference sets and exceptions in words, so an independent recount gives the frozen list without reading the code. Recounts in Node round ties to even, as Python does (`scripts/half/fixtures/parity.json`).
- **Follow a fallback into every slot**, and recount each slot in a verifier: a review found a story whose H1 fell back while its figure, repeated in four places, still showed the number the guard had rejected (rule 13).
- **Two numbers on one screen must add up.** Derive a displayed difference from the displayed values; name the measure when a pooled and a per-window figure sit together.
- **Numbers on pages come from data files, never from typed copy;** a verifier recounts each one.
- **Look at what you ship.** Regenerate share cards and open the PNGs; capture changed pages at phone and desktop widths in light and dark and read them. Text extracted from rendered HTML can show a space between React text nodes that the page does not have. A review round judged by the agent that made the fixes is not independent. ([Design system](docs/DESIGN_SYSTEM.md).)
- **Check the push in a clean checkout of the exact commit,** push by sha when other agents share the worktree, and never commit another agent's unfinished edits. Read the remote (`git ls-remote`) and the pull request's checks again after every push. ([Before you push](docs/OPERATIONS.md#before-you-push).)
- **A first-load budget overage is usually an accidental import.** Pass words as props from server pages instead of importing tool libraries into client components; re-measure a budget only for an intended feature, with a dated reason.
- **A skipped or no-op CI job is not a pass;** find the run that did the work, or the dated local receipt.
- **A merge moves dates.** Pages whose visible text changes take the merge day in their sitemap `lastmod`, so set the merge-day fields on the day of the merge (`published` in `lib/stories.ts`, `CONTENT_DATES` in `lib/seo-routes.ts`); a data date that equals production's tells search engines nothing changed. The repository squash-merges (every pull request since #57), so a pull request already merged into another branch does not show as merged when that branch lands: merge it into `main` first, then bring `main` into the other branch. ([Merging](docs/OPERATIONS.md#pull-requests-merging-and-deploying).)
- **One heavy job at a time** on a small machine (builds, verifiers, browser scenarios, captures, source recounts); run Python that reads downloaded data with `python3 -I`, keep downloads in their own folder, and delete large temporary files.
