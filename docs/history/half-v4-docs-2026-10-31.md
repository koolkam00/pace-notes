## `analysis/README.md`

Lines 3, 52–53, 88–89, 91, 96, 107, 169–184 at `f8869591` (`main`; the same lines at `f761311a` on `feat/half-v4`): the release-immutability line, the module table's header and its half rows, the inputs line, the frozen-lists convention and the body of the half section.

The Python in this folder turns the owner's public data releases into the aggregate files under `public/data/` that every page reads, and imports them. It never scrapes races and never connects to the live ingestion database: every input is a published GitHub release, checked by SHA-256. The releases are not GitHub-immutable (the API reported `immutable: false` for `private-export-20261021-1050`, `half-dataset-20261029-1202` and `half-dataset-20261029-2157` on October 30, 2026), so the digests are what protect the inputs: the half downloader refuses any byte whose digest differs from `half-release.json`, the marathon downloader checks GitHub's digest and the release's own checksum file, and every output and refresh record keeps the archive and manifest digests it was built from, so a replaced asset shows up as a changed digest. This file is the calculation, import and per-release contract: which release is read, what each module writes and what verifies it, and the conventions the independent verifiers follow. The standing rules are in [AGENTS.md](../../AGENTS.md), the commands in the [operations runbook](../OPERATIONS.md), and the files and how to open them in [ACCESS.md](../../analysis/ACCESS.md).

- **Frozen lists, pinned inputs, loud failures.** Reviewed decisions are frozen as data and every input they rest on is pinned by SHA-256, so a changed input fails instead of drifting. `source_quality.py` applies a policy only to the exact tag it was reviewed for; the pacing workflow inspects an unreviewed tag and then fails. `build_half.py` recomputes every half screen and fails unless it equals the frozen list in the policy file, checks the corrected metadata's digest and the 72 withdrawn stamps against it, and fails on any count that differs from the reviewed one (`--accept-counts` only for a reviewed refresh, after reading every change). `verify-half-source` requires the frozen policy's rule text to equal its own constants. `build_course_terrain.py` refuses a new `course_profiles.parquet` hash until the correction registry is re-based on it. `calculation_provenance.py` refuses a pack whose builder hash is not the reviewed file.

The half pages read `public/data/half/`, built from the owner's public CC BY 4.0 half snapshot and its runner-links build (`half-dataset-20261029-1202`, doi:10.6084/m9.figshare.34858428.v1) with verified status from the corrected edition metadata of `half-dataset-20261029-2157`, all pinned by SHA-256 in `half-release.json` (schema 2). An edition is verified only when it is stamped in both the snapshot and the corrected metadata (the pin's `metadata_correction.applied`: "verified = stamped in both"). The pin keeps the first private releases' names (`half-snapshot-20261029-1133`, `runner-links-20261029-1156`) as `private_tag`, the identities the policy and counts are keyed by, and its `marathon_release` must equal the tag in `release.json`. The pages publish aggregates only: every shown group holds at least 100 finishes or pairs, and a claim across editions rests on at least 3 editions. The half work was merged to `main` by PR #85 (`a2c6e507`, October 30, 2026); its deployed state is in the handoff's [Current state](../PROJECT_HANDOFF.md#current-state).

The downloaded files are kept outside the repository (`PACE_HALF_DIR`, default `~/data/half-1133`). `download_half.py` fetches and checks them anonymously; `half_links_extract.py` cuts `links-slim.sqlite` (medium and high links of people in both databases, person keys hashed, no names) from the links release, from its SQLite or its parquet form alike; `half_quality.py` holds the reviewed policy (`REVIEWED_HALF_POLICIES`: record rules R1–R7, edition rules E0–E8, the stamp correction, `use_sex`, date suspects, the same-city labels; the reviewed lists, the 72 withdrawn and six weaker-source stamps in `half_policy_lists.py`) and freezes it as `half-policy-20261029-1133.json` with `--write-policy`; `half_marathon.py` reads the marathon side from the public runner shards and the weather evidence; `half_pairs.py` builds set B (nearest earlier half 21–112 days before each eligible marathon, one pair per person and marathon); `half_field.py`, `half_women.py` (its band medians only from at least 20 editions; with fewer they are left out), `half_linked.py` and `half_cards.py` build the families; `build_half.py` checks the sources and the corrected metadata against the pin, asserts every count and writes the family files and `manifest.json`. Run them with `python3 -I` (DuckDB `PACE_HALF_DUCKDB_THREADS`, default 2; `PACE_HALF_DUCKDB_MEMORY`, default 4GB; spill to `TMPDIR`):

```
python3 -I analysis/download_half.py [--out DIR] [--only half|links|correction] [--from-dir DIR ...] [--links-work DIR] [--keep-links-sqlite] [--replace]
python3 -I analysis/half_links_extract.py --links-sqlite FILE | --links-parquet DIR [--out FILE] [--pin]
python3 -I analysis/half_quality.py --write-policy | --check --half FILE [--corrected-meta FILE]
python3 -I analysis/build_half.py [--half FILE] [--links FILE] [--corrected-meta FILE] [--out DIR] [--accept-counts]
python3 -I -m unittest discover -s analysis -p 'test_half.py'   # PACE_HALF_SOURCE_TESTS=1 also recomputes the frozen lists and stamps
npm run verify:half-source                                      # the local Node recount; writes docs/evidence/half/source-recount.json
```

`download_half.py` asks only `https://github.com/<repository>/releases/download/<tag>/<asset>`, with no token, cookie or `Authorization` header (never api.github.com). `--out` defaults to `$PACE_HALF_DIR` and is refused inside the repository; `--from-dir` (once per folder) takes folders already filled from the releases with their `SHA256SUMS` instead of downloading; `--only` fetches one of the three sources; `--replace` replaces a file already in `--out` (a file already there with the pinned digest is otherwise kept). It requires each release's `SHA256SUMS` to list every pinned asset with its pinned digest, checks each download as it streams, reassembles and checks the SQLite (`PRAGMA integrity_check` and the pinned digest), cuts the links extract (the 5.3 GB links SQLite can go on another disk with `--links-work`, and is deleted afterwards unless `--keep-links-sqlite`) and puts the corrected metadata in `$PACE_HALF_DIR/<its tag>/`; about 10 GB of free disk at the peak. A build takes about 2 minutes and two builds give the same bytes; it writes no temp file over 1 GB and removes its own. A count that differs from the reviewed one fails the build (`--accept-counts` only for a reviewed refresh); a new snapshot or corrected metadata fails until its lists are reviewed. `half_cards.py` writes the plots of the "From the half" cards, whose words are `lib/charts/text/half.ts` and whose images `node scripts/build-chart-cards.cjs --set half` draws while each card's guard holds. The nuggets are `lib/nuggets/half.ts`, recounted by `scripts/nuggets/half.cjs`.

`scripts/verify-half.cjs` (in `npm run verify:data`) recounts the half-only values from the published aggregates and the marathon side from the public shards, checks the linked aggregates for consistency and fails unless the receipt of the independent Node recount (`scripts/verify-half-source.cjs`, about 90 s and 1 GB) binds the current manifest and recount scripts: after any rebuild, or any change to the recount, run `npm run verify:half-source` and commit the new receipt. The **Half marathon** workflow's `source` job downloads the public sources and rebuilds and recounts in CI when the pin, policy, builders, downloader or recount change. The contract and dated evidence are in [half marathons](../HALF_MARATHON.md); the refresh steps in [operations](../OPERATIONS.md#half-refresh).
