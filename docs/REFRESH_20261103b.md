## Why an adapter

A `master-*` release is one results table for both distances (`master_results_FULL.parquet`, with a `distance` column), an edition table (`editions.csv`) and the producer's QA files. It has no hourly weather, course profiles, `features.parquet`, `MANIFEST.json` or per-edition documents, so the builders cannot read it. [`analysis/adapt_master.py`](../analysis/adapt_master.py) writes the folder they read unchanged (design: the study of November 4, summarised here):

- `race_records.parquet`: the `in_core` marathon rows in 1050's 20 columns and types, ordered by id. Master's marathon `source_record_id` is 1050's canonical `race_records.id` (`record_uid = 'M-'||id`, checked on every row).
- The overlays from `dataset-20261103-0706` (`marathon-*.csv.zst`) in 1050's schemas. `race_conditions`, `course_profiles` and `course_segments` are value-equal to 1050's members, so 1050's own bytes are kept (`a2efadb4…`, `afd01df4…`, `ecc37923…`; the course-terrain registry and the weather evidence pin these hashes). `edition_meta` (plus a New York 2026 row from `editions.csv`, its other fields null), `record_flags` (master's detail table, restricted to the written ids) and `sources` are rewritten.
- `features.parquet`, an identity subset: labels, section and cumulative minutes parsed from the raw strings with the pacing parser, and the producer's v1 `runner_id` as `runner_id`/`match_key` (`is_ambiguous` false where a key is present, null where it is absent; `yob` from a `yob:` key). No producer engine column (`valid_splits`, `wall_*`) is written, and none is read by a builder.
- `MANIFEST.json`, `EDITIONS.json`, `races_summary.json`, `EDITION-CHECKSUMS.csv`, `RECONCILIATION.json` and the notes say on their first line that they are adapter outputs, not producer claims. `MANIFEST.created_at`, which becomes every output's `input_as_of`, is the release's `published_at`; master's README snapshot line ("marathon DB read 2026-11-03 16:31 ET") is kept beside it as `producer_snapshot_claim`.

The pin, [`analysis/release.json`](../analysis/release.json), now has `layout: master` and names every asset by digest, the overlay release and the 1050 CORE baseline; `repository` and `tag` stay for the existing readers. [`analysis/weather-release.json`](../analysis/weather-release.json) names the same tag and its `race_conditions` overlay. `download_release.py --bundle FULL|CORE` hands a master pin to the adapter, so every workflow step keeps working; CORE is the same folder without `features.parquet`.
